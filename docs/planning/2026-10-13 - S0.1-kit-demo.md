## 2 · Cómo levantar el prototipo

Los datos son de prueba y viven **en el navegador** (cada navegador tiene los suyos). El botón "Reiniciar
datos de demo" (arriba a la derecha) los deja como al principio.

| Opción | Comando | Para el celular (QR) |
|---|---|---|
| **A. Notebook en la misma Wi-Fi** (recomendada) | `cd apps/web && VITE_PUBLIC_URL=http://<IP-de-la-PC>:5173 npm run dev -- --host` | El celular abre `http://<IP-de-la-PC>:5173` |
| B. Stack Docker local (igual que producción) | `docker compose --profile completo up -d --build --wait` | Solo se ve en la propia notebook (`http://localhost:8080`, puerto atado a `127.0.0.1`); para el celular usar A |
| C. Staging público (cuando se autorice S0.9) | `scripts/desplegar-staging.sh` | `https://siset-staging.vertexall.com` |

Usuarios de prueba (contraseña `demo123`, también en el recuadro "Usuarios de prueba" del login):

## 3 · Guion de 10 minutos (`docs/product/prototipo-pantallas.md` §10)

1. Login `secdir` → **Nueva hoja de ruta** → mostrar el **QR** y la carátula.
2. En el celular: consulta pública de **HR-2026-000123** + CI 6098765 (ver la nota de arriba).
3. "Ver como" **SEC_COORD** → recibir el pase.
4. "Ver como" **KARDEX** → abrir el file, semáforo, tomar el trámite y **enviar a dictamen**. Mostrar un file **bloqueado**: el sistema no deja avanzar.
5. "Ver como" **COORDINADOR** → aprobar el dictamen.
6. "Ver como" **KARDEX** → vista previa del PDF con marca de agua → emitir.
7. "Ver como" **SEC_DIR** → recibir el retorno → firma → entrega.
8. Celular: el **timeline** muestra el recorrido.
9. Cerrar con **Reportes** y **Bitácora** ("cada paso quedó registrado": DEC-007).
